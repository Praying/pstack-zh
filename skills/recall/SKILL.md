# Recall（回想）

**开始或恢复工作之前，先重建用户最近的工作上下文，交回一颗紧凑的胶囊，装着现状和下一步。**

紧扣主题，保持紧凑。只读范围内线索需要的东西，读完就停。

你的上下文存在两份记录里。你自己的聊天记录记着你做了什么、决定了什么。共享档案记着同一份代码在其他名下发生的一切：用户反复报的症状、发了又回退的修复、生产环境还在冒的错误。第二份记录住在源码管理、问题跟踪器、聊天和问题频道、长文档和错误跟踪里。bug 尾巴长的功能，故事大半在那里，所以不要只凭你的转录（transcript）重建。

转录存放在 `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`。`<slug>` 是工作区路径去掉开头的斜杠、每个 "/" 换成 "-"（所以 `/Users/you/proj` 变成 `Users-you-proj`）。每行是一条聊天消息。

1. 先分类，再分流。要续上某一场特定的旧聊天，那是 `session-pickup` 手册（playbook）的活，不是这里的。把习惯变成持久技能（skill）是 `automate-me` 的活。给人读的工作总结是另一回事。Recall 的职责是在你动手之前，把最近各场聊天里的工作上下文装进来。用户已经给过你完整的状态胶囊（路径、分支、改动），就直接用，跳过挖掘。
2. 搜索前先锁范围。钉死时间窗（"最近"是一个真实区间，默认最近 7 天）、点名了的主题、以及工作区（默认当前活动的。没被要求绝不读别的项目的转录）。把范围复述出来。绝不悄悄把"全部"换成"最近 N 条"。
3. 在你的聊天史里扇出。用快而便宜的模型派并行子代理（subagent），各切一片语料。告诉每个子代理按真实修改时间（`ls -t`）排序候选，绝不按 UUID 名排，先 grep 主题，再只读命中的聊天和其中相关的段落，跳过当前这场聊天和明显的噪音（子代理、eval 和测试聊天）。每场聊天返回同样的结构，一个块：主题、用户目标、决定、未结线索、挣扎与修正、产物（PR、工单、分支），各自引聊天 UUID。只有一两场聊天就别扇出，直接搜。原始转录留在子代理里。主线只拿它们的发现。按任务为每个子代理挑选推理等级，见 **poteto-mode** 技能的子代理（Subagents）一节。
4. 只要点名了功能、文件、子系统、区域或 bug，就要清扫（sweep）共享档案。这是默认动作，不是可选判断，"我在 X 上的活"也不例外。每个来源派一个调查子代理，用代理（agent）模式，因为 readonly 会剥掉 MCP 访问权限，问每个："现状如何、试过什么没站住、用户还在报什么"。与聊天史挖掘并行跑。查无结果也是发现。MCP 不可用就跳过并说明。把回来的东西折进简报。只有纯活动回顾且没有点名目标（"这周我干了什么"）才跳过这一步，那时你自己的历史和实时状态就是全部答案。
5. 对照实时状态验证。把挖掘和清扫浮出的 PR、分支和工单拿 `git` 和 `gh` 核一遍。答案取决于某个代理实际做了什么（它跑的工具、读的文件、撞的错误）时，读完整转录，不要只读删节的本地副本。
6. 按下面的契约写简报。按线索分组。紧扣点名的主题。

## 输出契约

胶囊打头，然后是线索状态，然后是问题，然后是下一步。更深的细节放下面，或者砍掉。

- **胶囊。** 最多 5 条。这摊工作是什么，整体到哪了。
- **线索。** 每条一行，前缀只贴一个状态标签：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。没贴标签的线索就是没完事，贴上。
- **问题。** 最多 5 条，要反复出现的。把用户反复报的症状、发了又回退的修复都收进来，让下一次尝试从上次失败的地方起步。
- **下一步。** 单个最有用的下一步动作，要具体。

相邻的功能或工单不进来，除非它挡着这一摊。胶囊和线索行超过一屏时，先砍细节，再砍线索。简报写完过一遍 **unslop** 技能。聊天发现引 UUID，共享档案发现引来源（PR #、工单 ID、聊天永久链接、错误跟踪器 issue）。任何公开输出之前清理私密上下文。

**回复：** 简报，按上面的契约。
