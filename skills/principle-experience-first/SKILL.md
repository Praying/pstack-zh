# Experience First（体验优先）

实现顺手与用户愉悦冲突时，选愉悦。

- 每个功能、控件和选项都必须有存在的理由
- 少发一点，发好一点（打磨过的三个功能胜过粗糙的十个）
- 动手前先做原型（在一次性 HTML 里做设计决策，比在生产代码里便宜）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能都该服务核心工作流，要么就让路）

用户就是消费这份工作的人。对 UI 来说是最终用户。对库或内部 API 来说，是导入它的同事。下一个维护这份代码的工程师也是用户。用同样的方式权衡他们的体验，从他们的视角解释影响。

基础应当服务于体验。Foundational Thinking 管的是工作的*顺序*。这条原则（principle）管的是*目标*。
