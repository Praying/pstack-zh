# Outcome-Oriented Execution（面向结果的执行）

为预期的、可验证的终态做优化，而不是保住平滑的中间状态。

**为什么：** 让每个中间步骤都完全稳定，往往造出临时兼容代码，拖成长期债务。向目标架构收敛，在明确的验证边界处证明正确性。

**核心规则：**
- 终态完整性优先于过渡期稳定
- 中间的破坏可以接受，前提是计划过、范围明确、且可逆

**护栏：**
- 把它用在有明确阶段边界的计划性重写和迁移上
- 声明清楚哪些地方可以接受临时破坏
- 迁移期间，给正在动的区域保留高信号检查
- 计划完成时，要求完整的静态与运行时验证
