# No comments（不留注释）

派生 Comment Sicko。对被接受的发现项动手。

尊重 Comment Sicko 的新鲜视角。

## 范围

用调用方给的文件或 diff。否则用当前分支相对基线分支（默认 `main`）的那份 diff，包含工作区。

## 步骤

1. 用 `Task` 派生，`subagent_type: "comment-sicko"`。把范围传过去。按 **poteto-mode** 技能（skill）的子代理（Subagents）一节，为这份工作挑子代理的推理档位。不要复述它的规则。
2. 检查它的报告和 diff。以下一律拒收：动应用代码、越出范围、靠例外条款保护的删除、说错的 `MUST KILL` 理由，以及把刻意保留的代码标成有罪的标记。针对我们代码意外之处提出的重塑标记仍然可执行。那些注释不要恢复。一个保留判定要成立，只有证据表明它讲的是我们改不了的东西。清查漏网的有作用域的 lint 和 TypeScript 压制注释。涉及正确性或安全的压制注释仍是可执行的 `MUST KILL`。只有例外条款精确对上、并有作用域内的证据，才恢复被删的注释。接受理由单薄的 `IMPORTANT` 或 `do not remove`（无论是删是留）之前，先追它的符号，或者对它跑 `/why`。一个删判定模棱两可，就不要恢复。一个留判定被驳倒或仍然模棱两可，就删掉它。挑一份被拒的报告，点名失败之处，回滚并重跑。第二份再被拒，就把它作为未决事项报出来，并让 `/no-comments` 失败。
3. 被接受的琐碎标记直接修：删掉死路径、去掉一个参数，或者改用真正的 API。哪个修复需要结构方案，就针对被接受的集合和周边代码跑一次 `/architect`。停在草图。architect 只出结构。第 4 步做实现。
4. 在范围内实现最小的根因修复。删掉每一个被点名的变通做法。根因在范围外的话，就落一个范围内的最小修复，其余作为未决事项报告。**principle-fix-root-causes** 和 **principle-redesign-from-first-principles** 技能只指导意图。它们都不授权扩大围栏，也不授权修围栏外的实例。绝不硬加症状护栏。
5. 约束注释会写 `do not remove`、`do not change wording`，或者 `talk to X before changing`。讲我们改不了的东西的保留判定留着。提供范围内代价最小的手段：类型、运行时、测试，或者 CI lint。等交互式批准。无人值守和评估场景需要调用方预先批准。批准了就先编码再删。否则删掉，把约束作为未决事项报告，并勾勒范围外的工作。
6. 报告删除数量、恢复的注释、重跑、架构草图、修复、编码提议、已做的编码、未被强制的约束，以及其他未决工作。
