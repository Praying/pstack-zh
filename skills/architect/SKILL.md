# Architect（架构设计）

写代码之前，先追一遍这次改动牵动的每个系统，然后为它勾勒两种不同的结构方案（类型、签名、模块边界），挑出这样一种方案：每份状态只有一个所有者，每项任务只有一种做法，调用方需要知道的最少。变通做法反复出现的话，就重新设计，不要打补丁。

大型或者有争议的设计，跑 **arena** 技能（skill），不要自己一个人勾勒。
