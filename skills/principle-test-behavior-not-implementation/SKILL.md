# Test Behavior, Not Implementation（测行为，不测实现）

测试是一个主张，说的是代码的用户通过接口能观察到什么：返回值、错误、能读回的状态，以及对外部系统的影响。私有助手、内部调用顺序、中间数据，这些属于实现。

用两种想象中的改动评判每个测试：

- **破坏行为**（给错值、跳过或翻倍某个效果）。测试还过，就什么都没证明。常见原因是断言太松、期望值由被测代码算出、断言打在测试自己构造的数据上。
- **改动内部**，同时保持每个可观察结果不变。测试挂了，就说明它钉死在实现上。

保留能抓住第一种改动、扛过第二种改动的测试。其余的重写或删除。用具体输入通过公共接口驱动代码，从需求推出期望值。外部服务收到的东西是行为。调用内部助手不是。给"这事从不发生"配上一个它确实发生的情况。断言调用方拿来分支的错误类型，不是错误消息。
