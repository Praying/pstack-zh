### Session pickup（接手会话）

**你拥有续跑点（resume point）。读之前的轨迹，不许重做。**

1. 定位到之前的轨迹。轨迹是活动工作区 `agent-transcripts/` 目录下的一份本地转录（系统提示词（prompt）会给出这个路径。不要用 glob 扫 `~/.cursor/projects/*/`，那会跨过工作区边界，读到无关项目的私密对话）、一个云代理 URL，或一个推上去的分支。先读元数据概览和最后几条消息，再往回扫，找决策点。长转录（transcript）交子代理（subagent）解析，削减后的时间线留在主线程（**principle-guard-the-context-window** 技能（skill））。照子代理（Subagents）一节给每个子代理挑推理档位。
2. 重建操作状态。分支和工作树（worktree）、哪些已经落地（`git log`、与 base 对比的 `git diff`）、开着的待办项、做过的决定。之前的轨迹是权威输入。克制住重新推导它的冲动。
3. 把已完成和待处理做一次 diff。把交付了的对照计划过的，定下续跑点，不许重跑之前的复现，不许重做已完成的工作。跑一遍"让我从头验证"，就是把权威的轨迹当成了不可信。
4. 把剩余工作路由到匹配的手册（playbook），并选定裁定（verdict）：继续执行、交付一份成型的建议、批准或推翻之前的结论、或给一次失败的运行做复盘。接手手册到此为止。路由到的那本手册负责其余。
5. 在真实产物上、对着原始目标，验证继承来的论断（**principle-prove-it-works** 技能）。之前自我报告说通过，不算证明。

**回复：** 之前的代理（agent）停在哪、你继承了什么、重做了什么（最好什么都没重做）、续跑点、结果。
