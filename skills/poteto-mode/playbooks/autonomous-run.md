### Autonomous run（自主运行）

**你拥有退出条件。先定义完成，然后不停歇地开到那里。**

1. 在第一轮迭代之前，把退出条件说成一个可检查的谓词（测试全绿、复现修好、N 个 PR 全合并、像素 diff 为零）。
2. 用 Cursor 的 `/loop` 命令选唤醒机制（它是内置的，不是 pstack 技能）。有事件可看（CI、合并、ref 前进）就派一个看守子代理（subagent），事件发生时叫醒你，再配一个长时间的心跳兜底。没有事件就用心跳，间隔按结果值不值得重查来定。照子代理（Subagents）一节给每个子代理挑推理档位。
3. 每轮迭代只做证据支撑的最小改动，对着谓词验证，有推进就提交（commit），没帮上忙的改动丢掉。"可能有用"的双保险做法要回退，不许留着搭车。
   用 **sequence-verifiable-units** 原则（principle）技能（skill）给工作排程，每个单元验证过再进下一个，不要把检查攒到最后一起跑。
4. 运行途中发现的、有助于目标的事情都归你处理。坏掉的技能、相关的 bug、飘忽的验证器、审查噪音、工具故障、没人管的跟进项、能修的漂移，都按 poteto-mode 自己处理。带外修复放进单独的 PR。不要把可逆的工作停给人类，也不要用 `AskQuestion`。只有不可逆动作、任何实验都定不了的产品或偏好取舍、真正的死胡同，才摆到台面上。谓词始终是主驱动，每次顺手修完都要回到它。
5. 每轮迭代都用 **show-me-your-work** 技能打检查点，一行记下改了什么、谓词动没动。
6. 谓词满足就停。高原期不算停，继续走，换个路子翻过去。真死胡同就摆出来，不要原地空转，绝不放宽谓词来宣布胜利。

**回复：** 退出条件、跑了几轮、落地了什么、丢弃了什么、谓词的最终状态。
