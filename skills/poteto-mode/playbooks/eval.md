### Eval（评估）

**你拥有实验设计。计划、盲化、运行、综合。**

**盲化的不可协商项：**

- 候选者能看到的任何目录、文件或提示词（prompt）里，都不许出现 `eval`、`test`、`judge`、`experiment`、`rubric`、`score`、`compare`、`benchmark`、`candidate` 或 `arena`。
- 给候选者的提示词要像一个自然的用户请求。说目标，别说元信息。
- 不许有诱发思维链的线索。不要让候选者列出他们用了哪些技能（skill）、原则（principle）或文件。一般性地要设计笔记，从代码形状给链路遵循打分，不看自我报告。
- 清洗目录名和 slug 名。用用户会起的、像真实项目的名字。
- 不要告诉候选者还有别的候选者存在。
- 评审（judge）可以知道自己在评审，但只能看带清洗标签的输出，绝不给模型名。
- 比较两个变体时：一个评审在一轮里用同一把尺子给两组打分，对哪组出自谁保持盲态。

**步骤：**

1. **定框。** 说清测的是哪个变体、什么行为算成功。评分标准（3-6 条具体判据）只写给评审。对候选者扣住不给。
2. **布置清洗过的环境。** 每个候选者一个工作目录，变体放好。种下自然任务该有的上下文：项目骨架、候选者本来会读的那些技能。
3. **写一份自然的提示词。** 就是用户会打出来的那种。不许泄漏在测什么。
4. **派生 N 个并行候选者**，按 **arena** 技能的 Phase B 用不同模型。每个在自己的清洗目录里干活。每家同一份提示词。照子代理（Subagents）一节给每个子代理挑推理档位。只负责派发、轮询或打包结果的代理（agent）跑 `claude-opus-5-5-medium-fast`。
5. **派生一个盲化评审**，按 **arena** 技能的 Phase C 用不同模型家族。评审只看带清洗标签的输出和评分标准，绝不给模型名。
6. **从转录（transcript）验证链路，不看自我报告。** 读每个候选者在当前工作区 `agent-transcripts/` 目录下的本地转录（系统提示词指明了这个路径）。不要跨 `~/.cursor/projects/*/` 去 glob。那会越过工作区边界，读到无关项目的私聊。看每个候选者实际打开了哪些文件。从它真正读过的文件加代码形状给链路遵循打分，绝不看候选者自己的说法。
7. **亲自通读每个候选者的输出**，从头到尾。对照评审的裁定。不一致说明某个模型有偏见，或者评分标准含糊。做综合。

**回复：** 受测变体、评分标准、每个候选者的笔记、评审的裁定、你的综合、以及要不要推广该变体的建议。
