### Runtime forensics（运行时取证）

**你拥有诊断。给活进程插桩，不要对着源码空想。** 交付物是带引用的诊断，不是修复。

1. 用控制技能在相配的界面上抓活信号：空转进程抓 CPU 画像，泄漏抓堆快照，视觉毛刺抓 CDP 追踪。要真产物，不要猜测。
2. 把产物削减到铁证：热路径上的那个函数、从泄漏对象到 GC root 的持有链、没有输入却在触发的循环。大产物交给子代理（subagent）解析（**guard-the-context-window** 原则（principle）技能（skill）），削减后的发现留在主线程。照子代理（Subagents）一节给每个子代理挑推理档位。
3. 先证明机制再相信它。用 CDP eval 往运行中的进程注入插桩，或不重载地热修活代码，便宜地确认假设。
4. 把发现映射回源码：文件、符号、分配或调度的那一行。
5. 吞吐检查点只留一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 抓到的信号、削减后的发现、你怎么证明机制的、源码位置、产物路径。除非被要求，不给修复。成因弄清后交还给 Bug fix 或 Perf。
