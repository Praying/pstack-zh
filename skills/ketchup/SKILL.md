# Ketchup（补课）

把这次对话里、用户在 `/ketchup` 之前写的最后一条消息以来的变化讲给用户听。帮他们理解每处变化，不只是知道现状。然后摆出所有等他们拍板的决定，让他们只凭你的回复就能拍板。通知和子代理（subagent）的结果不算他们的消息。假定用户只记得自己最后一条消息，之后的事全不记得。

用 [`/bro`](../bro/SKILL.md) 的语气，不用它的任务：大白话，短句子，不带行话，像一个人给另一个人讲进度。说用户那边什么变了，不说你怎么做的。说"测试过了"，不说"CI 是绿的"。哈希、文件路径、命令、构建号、测试数量统统省掉，除非用户做决定要用到。每个 PR、分支或代理（agent）都用用户认得的名字称呼，不要用你自己发明的标签。某个事实要配上下文才说得通，就给出上下文，否则连事实一起省掉。

## 收集变化

这一轮保持只读。做图示只用你手上已有的材料。不改代码，不启动应用或任务，不发布任何东西。收集那条消息以来你自己的工作、子代理的报告，以及这场对话里其他人的消息。查清这场对话碰过的每个 PR、CI 运行或代理的当前状态。你要展示的每个数字都对照它的出处核一遍，改了哪个就说一声。

行动项是只有用户能做的决定或步骤，比如产品取舍、批准、不可逆的动作，或者你没有的权限。凡是还等用户的都算，哪怕它在用户上条消息之前就提出来了。你自己还能做的工作不算行动项。绝不要为了填满回复而编一个决定。用户没要求、工作也不需要的步骤不算行动项，除非它不可逆且正等用户。给它一行字，不配图。

一个决定可以覆盖多件事，比如一组待合并的 PR 里的每一个。对每件事，收齐它的链接、它给用户带来什么变化、你的选择背后的证据、它的风险，以及你的选择。决定要用到而你不知道的事实，写"未知"。没有的链接就不写。

## 写回复

笔墨花在决定上，不花在故事上。发生了什么控制在 100 词以内，图片不计，事少就更短。对用户没带来任何变化的工作不写。每件事约 30 词。回复随事数增长：两件事总共远不到 150 词（图片不计），三十件事要多得多。绝不要为了压字数而砍掉事情或把事情写小。不要用一个数字代替清单，不要用一个链接代替一件事。链接可以补充深度，但只凭回复本身就要足够做决定。

开头一句话，说清什么事在等用户，或者明说没事在等。细节由行动项给出。什么都没发生、也没什么事等用户，就直说，然后收尾。

然后展示发生了什么，图片打头。把工作产出的截图和视频内嵌进来，再放解释某处变化的图。然后按用户问过的每件事写一条简短要点：结果如何，是完成了、还在跑、失败了，还是没查过。每行写成你会说出口的话："搜索慢是因为缺了索引"，不是"搜索评审：完成"或"搜索慢：缺索引"。路上发现并修掉的 bug 也点名。每行单独读也必须成立。还在等用户的绝不要标成完成，行动项里写了的这里不再重复。摘要下面最多再给三行短句，改变用户认知或必须去做的事。然后用一行点名剩下你能自己做的工作。

然后列行动项。把用户拥有的决定问出来，比如合并、批准或挑选，并给出你的选择。你会先做的那一步写进你的选择。必须先发生的、不能撤回的，也都写进去。每个决定涉及的 PR、issue 或代理，给出编号或链接，选项之间的决定也一样。

形态跟着决定走。针对一件事的决定就是一条要点：决定本身、你的选择、它给用户带来什么变化、你的选择背后的证据、它的风险，事情只点一次名。多件事共用一个决定时，决定和你的选择写一遍，然后每件事各一条要点，风险最高的在前：它的链接和名字、它给用户带来什么变化、你的选择背后的证据、它的风险。事情的选择只有在与整体决定不同时才单独写。每件事的风险都要写，哪怕很低，比如"低风险：只改颜色"。等待的代价只在超过单纯延迟时才写，比如有截止日期或丢数据。

选项之间的决定，把工作权衡过的每个选项都摆出来，各写它给用户带来什么、代价是什么，有当前状态就写。这些代价就是决定的风险，不必另起一行写风险。上面的截图已经展示选项时，把每个选项的得失写在它截图下面。

## 图示

图示就是图片：截图、视频、Mermaid 图、来自 `/visualize` 的图表，或者生成的图片。Markdown 表格不算图示，哪怕有前后对比列。

有些东西看图比读句子好懂，就画出来：设计或系统怎么运转、带每个 PR 状态的 PR 栈或依赖链、修复前后的对比、并排的选项。绝不画状态清单、行动项清单，或者一堆互不相连的方框。同一个事实绝不给两遍，无论在文字里还是跨图示之间。

每张图示控制在一眼能读完的大小：最多六个方框，每个方框最多八个词。标签写成人会说的大白话，不要写成"Tests: pass"这类标签。需要一句话才说得清的事实，属于文字，或者干脆不写。

变化看得见时，把截图和视频内嵌进来，不要只给链接。看得见的变化没有截图，就在它的摘要行标上"暂无截图"，并在那里说明屏幕上什么变了。画图只依据你手上的事实：连接关系用 Mermaid 图，数字用 `/visualize` 图表。绝不编数字，绝不画或生成你没截过的屏幕。只链接真实存在的产物。
