# 控制适配器契约

Benny 不知道怎么启动和驱动每一个应用。用户必须配置一个为目标应用实现本契约的控制技能（skill）或适配器。

把它的技能名设在 `control.skill_name`。

把填完的用户可见功能地图（feature map）路径设在 `control.feature_map_path`。把 [`feature-map.example.md`](./feature-map.example.md) 复制到 `.cursor/automations/benny/` 之外填写，不要改复制出的示例。

技能、功能地图或任何必需能力缺失、含糊或不完整时，复现与修复工作必须失效关闭（fail closed）。

## 必需的能力

### 拉起

在请求的测试环境里启动请求的应用版本。

输入：

- 仓库与版本
- 构建或启动模式
- 工作区、账号、测试夹具（fixture）和功能状态要求
- 产物目录
- 填完的功能地图路径

返回：

- 会话标识
- 适配器如何确认应用和环境正确
- 稳定的应用标记
- 后续调用所需的运行进程或目标细节
- 任何缺失的能力

适配器必须把目标应用与相似的窗口、shell 或生产实例区分开。

### 驱动 UI

执行真实用户操作：

- 点击
- 输入
- 按键
- 滚动
- 拖拽
- 缩放
- 通过应用控件导航

优先用角色（role）、标签（label）和稳定选择器。只在刚截过一张新图之后才用坐标。

返回每个动作和观察到的状态变化。

不要为了制造症状去设置内部状态、调用隐藏的应用方法、直接写存储，或注入 DOM 改动。

### 驱动已映射的功能和状态

驱动应用前先读相关的功能地图小节。

适配器必须提供以下手段：

- 沿用户可见路径导航到每个已映射的功能。
- 调用该功能列出的适配器动作名。
- 在适用时与这些状态交互：默认、悬停、焦点可见、激活、禁用、加载中、空、错误、选中、打开、展开，以及功能特有状态。
- 用安全的夹具数据、权限、开关、服务响应或受支持的测试控制来铺垫状态。
- 为第二次独立复现重置该功能。
- 捕捉功能地图指名的截图、视频和只读交叉核对。

用角色、无障碍名称、ARIA 关系、稳定组件标记和表意的数据属性。绝不要用生成的 CSS 或 StyleX 类名、动态哈希、子元素下标或脆弱的 DOM 位置。

铺垫前置条件不等于允许注入报告里的症状。复现本身仍必须来自真实用户交互。

### 检查状态

读状态来确认 UI 显示的内容。

例子：

- 无障碍树
- DOM 或视图层级
- 进程状态
- 本地日志
- 网络请求状态
- 应用暴露的调试状态

检查是只读的。如果某个查询会改变状态，它就属于 `drive UI`，而且必须代表真实用户动作。

### 截屏

把当前应用状态截到请求的路径。

返回：

- 文件路径
- 截取时间
- 应用标记或窗口标题
- 一句说明应该看到什么

截图必须带出足够的应用外壳（chrome），证明被测的就是正确的应用。

### 录屏

围着完整复现路径开始和停止录屏。

返回：

- 文件路径
- 开始与停止时间
- 截取的窗口或区域
- 是否省略了音频或敏感浮层

录屏必须显示有区分度的最终状态，不能只有设置过程或加载画面。

### 清理

停掉适配器创建的进程和会话。

清掉一次性的东西：

- 浏览器或应用的配置档案
- 临时工作区
- 适配器创建的测试账号或夹具
- 调试端口和隧道
- 过了留存窗口的截图录屏

返回停掉了什么、删掉了什么、留了什么，以及留给人工处理什么。

清理绝不删用户的工作成果。

## 适配器行为

适配器必须：

- 复现开始前报告自己的能力。
- 报告哪些功能地图小节能驱动、哪些受阻。
- 基线（baseline）和打补丁的构建用同样的环境输入。
- 启动失败就如实报为失败。
- 限制重试次数。
- 密钥不进日志和产物。
- 截图录屏放在仓库之外。
- 两次复现之间支持全新或重置的状态。
- 避免改动生产环境，除非用户明确配置了安全的测试动作。

## 环境转译

在宣布环境受阻之前，先用不含平台专有名词的方式重述这个缺陷，并问清同一个行为能否在现有环境里安全测试。

例子：

- 点名的浏览器可能指任意外部浏览器。
- 点名的按键可能指配置的快捷键。
- 点名的远程主机可能指有延迟或断连的远程目标。

只有在测试同一个底层行为时才用转译后的尝试。把它标注为转译证据。当缺失的环境本身就是缺陷的一部分时，不要称其为精确复现。

硬件提示、操作系统权限对话框、仅设备可用的 API 和拿不到的账号状态，可能是真正的受阻。

## 设置检查

启用复现自动化之前，跑一次无害的适配器检查：

1. 拉起应用。
2. 确认稳定的应用标记。
3. 加载一个填完的功能地图小节。
4. 沿用户路径导航到该功能。
5. 用映射的适配器动作遍历一个一次性状态。
6. 检查得到的状态。
7. 截屏。
8. 录一小段。
9. 清理。

只有九步全部成功、且全程不涉及源频道 Slack 发帖时，才启用复现工作。
